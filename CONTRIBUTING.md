# Have at it

Fixes, ideas, experiments, and PRs are welcome. You can start small or build something ambitious. Fork freely. A PR is an invitation to review; merging depends on how it fits the editor.

Keep Robbie's Compositor as the reference for core editing behavior, design, and project compatibility. Windows refinements are welcome. Explain intentional departures so they can be considered on their merits. For a large change to that foundation, opening an issue first can save you work.

1. Follow the [build guide](docs/source-package.md).
2. Make the change. Human and agent-assisted contributions follow the same process.
3. Run the checks affected by it. For UI work, include an actual screenshot or recording; for a bug, describe how to reproduce it.
4. In your PR, explain what changed and how you checked it. Be clear about anything untested.

Use issues for bugs, ideas, and questions. A useful bug report includes the Windows preview version, steps to reproduce, expected/actual behavior, and a small example when possible. Remove private information from projects and screenshots before uploading them.

Write clear code and reuse the existing tests. Update a guide when a user workflow changes. Avoid generated reports, agent diaries, parallel specifications of the code, and new status files. [AGENTS.md](AGENTS.md) gives coding agents the same working boundaries.
