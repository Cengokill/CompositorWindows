# Adjustment primitives

`src/effects/Adjustments.h` exposes `defaultAdjustmentJson(kind)`, `validateAdjustmentJson(json)`, and `applyAdjustment(source, json, selection, region)` in `compositor::effects`. The JSON uses the same complete Codable `LayerAdjustment` representation as project persistence. Kind strings are exactly `Hue/Saturation`, `Levels`, `Curves`, `Exposure`, `Gradient Map`, and `Grain`. Unknown kinds and malformed settings throw. Optional legacy settings resolve to the pinned defaults.

The input is an immutable `Raster`. Selection, when supplied, is grayscale coverage already mapped to its pixel grid; absent coverage allows the entire image, and all-zero coverage edits nothing. The operation returns the original handle for identity settings or unchanged output. Only changed 256×256 tiles are replaced; unselected tiles remain shared. `AdjustmentRegion` specifies the source image's document origin and document units per pixel so grain stays fixed across partial renders. It does not apply layer geometry or decide adjustment-stack scope. Those remain responsibilities of the caller and canonical compositor.

| Kind | Pinned source behavior used |
|---|---|
| Hue/Saturation | `HueSaturation.swift:26–58, 170–213, 253–360`: seven range weights and inverted selected band, 361-entry hue response, 33³ float RGB cube with red varying fastest, HSL adjustments and colorize defaults. Native lookup uses explicit trilinear interpolation on straight RGB then restores original alpha. Mac interpolation/rounding comparison remains blocked. |
| Levels | `Levels.swift:8–44, 64–99` and `LevelsPixels.c`: per-channel LUT followed by composite RGB LUT; the **actual pinned wrapper sequence**, including its extra unpremultiply/premultiply around the C routine, is retained. This causes the known source/test conflict below. |
| Curves | `Curves.swift:3–40`: shape-preserving cubic Hermite interpolation, endpoint slopes, harmonic interior slopes and channel-then-master order; actual upstream `levels_apply` performs the premultiplied pixel lookup. |
| Exposure | `ImageAdjustments.swift:37–71`: decode sRGB to linear, multiply by 2^stops, add offset, apply gamma and encode to sRGB; actual C LUT routine retains alpha. |
| Gradient Map | `ImageAdjustments.swift:75–100` and `AdjustPixels.c:4–27`: rounded 256-color endpoint table, integer 2126/7152/722 luminance weights, reverse and exact alpha arithmetic. |
| Grain | `ImageAdjustments.swift:104–143` and `AdjustPixels.c:29–95`: actual C algorithm, supplied UInt32 seed, global origin/scale, lattice and fine noise, midtone weighting. |

Selection blending implements `(coverage * adjusted + (255 - coverage) * original) / 255` with nearest-byte rounding. Fully covered and unaffected pixels stay exact. Source `PixelAdjust.swift:37–49` uses a floating Core Image blend with disabled color conversion; soft-edge rounding and HSV lookup remain `blocked_reference` until Mac comparisons establish agreement. No operation-specific tolerance has been relaxed. [Apple's cube data contract](https://developer.apple.com/documentation/coreimage/cicolorcube/cubedata) confirms float RGBA table layout and R/G/B order; it does not establish exact equality for this Windows sampler.

Run `windows/tests/effects/run.ps1`. `build-run-1.log` and `results.xml` record ten native checks passed, zero failed/skipped, under Qt 6.8.3/MSVC 19.44. These cover identity handles, upstream exposure expectations, constant-white curves through soft alpha, gradient endpoints and midpoint, grain cropped across multiple tiles, primary HSV hue/alpha, range-aware HSV/colorize, empty/soft selections and shared tiles, settings rejection, and opaque Levels channel order. They are bounded analytic/implementation checks, not complete ports of all source test methods or Mac differential results.

## Unresolved source/test conflict

`SOURCE-TEST-CONFLICT-LEVELS-ALPHA` remains **fail**. `Levels.swift` unpremultiplies RGB before calling `levels_apply`, which already performs that conversion, then premultiplies again. With input `[64,32,0,128]` and inverted output endpoints, the exact pinned sequence produces `[0,32,64,128]`. `LevelsTests.inputClippingGammaOutputInversionAndAlpha` expects `[64,96,128,128]`.

The separate command `effects_tests.exe levels_upstream_conflict` exits **1** and writes the actual/expected arrays into `tests/effects/levels-source-test-conflict.json`. The runner explicitly checks that this characterization still fails; it is outside the green native suite and must remain in the overall parity ledger. The implementation preserves the pinned behavior. Fixing the double conversion or changing the expectation requires Mac reference evidence and an accepted behavior decision. No failing comparison is relabeled as a pass.

Remaining work includes Mac cube/soft-selection references, full upstream assertion ports, histogram/auto-level/sampler and hue-editing controls, panel preview/cancel/history integration, live-stack ordering and clipping scopes, performance measurement and cache policy. The API currently validates complete JSON and reconstructs tables for each call; the renderer should cache compiled immutable settings before large interactive workloads. No production UI acceptance follows from these primitive checks.
