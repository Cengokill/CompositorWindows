# Layer graph operations

`src/layers/LayerOperations.h/.cpp` implements source document graph operations as immutable edits. Link `compositor_core` and `compositor_graphics`. Each operation accepts a `Document` snapshot and `SelectionState`, and returns `EditResult { document, selection, changed, action }`. The UI uses `changed` to preserve redo for a no-op and commits one history entry named `action` after success. A thrown error leaves the supplied document intact. UI busy-state eligibility remains the caller's responsibility.

The baseline is Compositor `a19db9011282399785dc18efcfded904627bdcc2`; source files and upstream assertions are unchanged.

| Operation | Pinned source | Contract |
|---|---|---|
| Hierarchy and grouping | `Document/LayerGroups.swift:3–45,64–119` | Parent links must point to folders; cycles and excessive nesting fail. Entries carry depth/effective visibility and support top-first/collapsed presentation. Grouping removes selected descendants from the root set, uses the nearest common parent, and inserts the wrapper at the topmost selected branch. An empty selection creates an empty folder. |
| New folder and moves | `LayerGroups.swift:136–199` | New folder inside the active folder or active layer's parent. Place rejects self/descendant parents, supports an explicit sibling drop target or bottom placement, adopts a contiguous clipping stack, then releases detached clipping links. Move Out places the layer above its former parent in the next ancestor. |
| Legacy reorder | `EditorSession.swift:568–596` | Flat top-first offset movement and same-parent sibling swaps preserve source behavior. These legacy reorder methods do not run clipping adoption/release; the modern `place` path does. |
| Duplicate | `SelectionClipboard.swift:147–174` | Ordinary duplicate/option-drag accepts one non-folder layer, creates a new UUID and ` copy` name, and shares immutable image/mask storage. Its existing clipping source is retained; drop placement runs source clipping repair. |
| Cross-project copy | `ProjectWorkspace.swift:155–211` | `copySubtree` includes descendants, remaps every internal layer/parent/clipping UUID, translates image and explicit-mask positions by one shared center delta, and appends to the destination. External live clipping dependencies are baked; external links on adjustments are cleared as upstream does. Both source snapshots stay unchanged. |
| Clipping | `LiveLayerMask.swift:3–70,196–230` | Sources cannot be folders or adjustments; targets cannot be folders; cycles/chains beyond the source limit fail. Toggle uses the lower sibling's existing base. Releasing a clipped layer also releases the contiguous higher siblings sharing that source. |
| Delete and bake | `LiveLayerMask.swift:74–152` | `deletionPlan` exposes the roots, descendant closure and surviving direct dependents. UI chooses Cancel, Bake, or Remove Links. Bake modifies only dependency-covered target pixels, retaining its own mask, opacity, blend, transform and other metadata. Multi-delete uses source sequential fallback selection and returns one edit. |
| Merge | `LayerMerge.swift:7–70` | `mergePlan` selects Merge Down, Merge Layers or Merge Group using source eligibility/anchor/name rules. `merge` sends the selected graph to `IRasterBackend`, detaches outside parent/clipping dependencies, composites the canvas, trims nonzero alpha, and retargets surviving clipping dependents to the merged UUID. A clear result retains the full canvas grid. |

Metadata and graph operations retain shared immutable rasters. Source and destination project budgets are checked before copying/baking. Bake/merge have a 1.2 GB default estimated working budget, 30,000-pixel side and 100-million-pixel raster limits. Bake polls cancellation during traversal. Merge checks cancellation around backend rendering and during trim; the supplied `IRasterBackend` currently has no in-flight cancellation method. Successfully baked dependency images retained during one operation count against its remaining working budget.

## Verification

`windows/tests/layers/run_checks.ps1` builds the standalone checks with MSVC C++20 `/W4 /WX`, then runs eight suites: `hierarchy`, `grouping`, `moves_duplicate`, `clipping`, `bake_delete`, `multi_history`, `copy_graph`, `merge`. Each suite can also be passed directly to `layer_checks.exe`. Output is saved under `tests/layers/results`.

All eight suites pass. Tests include the source nested-folder and hidden-parent rules; group wrapping/common-parent/selected-descendant order; folder duplicate rejection; shared images/masks on duplication; list index conversion; move eligibility; clipping toggle/release/adoption and cycle rejection; adjustment source/target eligibility; hidden black-source alpha; source opacity and dependency chains; transformed source movement; Cancel/Remove Links/Bake choices; immutable source and metadata preservation; multi-delete fallback and one-step history undo/redo; copy UUID remapping, explicit mask translation and external-link bake; merge name/anchor/retarget/trim/clear behavior; and a real renderer exception that leaves the original document intact. Pixel comparisons use the Windows `StackRenderer` on the source's small nearest-sampled alpha fixtures.

## Open parity limits

Bake uses shared `graphics/MaskSampling.h` and `RasterSampling.h`, so it agrees with the current Windows renderer's sampler. Smooth and High both use bilinear interpolation. Mac high-quality resampling, geometric antialiasing and fractional transformed mattes still need reference comparisons. Explicit placed-mask background follows source edge-majority semantics; masks exceeding 96 pixels use the shared area-downsample thumbnail surrogate because the core does not retain the source thumbnail. This can change threshold classification near a tie and remains unaccepted Mac parity.

Merge faithfully retains a source corner case: selecting both a folder and one of its children may choose the child as the highest selected record, then assign the merged result to the removed folder. Final graph validation rejects that operation atomically. This follows the current `LayerMerge.swift` plan and validation; there is no upstream merge test resolving the inconsistency. Do not claim that combination has a successful merge. Renderer blend/adjustment/color correctness and visual merge equivalence also depend on the separate renderer's open Mac reference gates.

Cross-project copy is the folder-copy API. The source's ordinary Duplicate Layer operation rejects folders, and this module preserves that restriction. Full UI drag/drop, collapsed-selection behavior, project switching during operations and interactive history acceptance remain integration checks beyond the standalone module.
