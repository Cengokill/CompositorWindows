# Composite viewport cache

`CompositeCache::render(doc)` still returns a complete exact-resolution image. `renderViewport(doc,x,y,width,height,unitsPerPixel,maxVisibleTiles,maxRetainedTiles)` returns a distinct `CompositeViewport`: a fully valid tight patch, its document origin and units per pixel, and the original document dimensions. No placeholder or invalid tiles are exposed. An empty intersection returns no patch. Full render has separate state and always fills every output tile; it cannot return a viewport patch as an export.

The requested document rectangle is clipped to the canvas. The sampling step is a power of two at least one and at least the requested document units per screen pixel. It increases until the aligned patch fits the visible tile budget. Defaults are 64 visible tiles (up to four million pixels) and 256 retained tiles (up to 64 MiB of unique pixel backing, excluding existing source tiles, metadata and externally retained results). At one-to-one or larger zoom, ordinary viewports retain exact canonical document pixels. Cache entries are immutable tile handles; unused entries are evicted by their last request. A different LOD resets its cache.

Every document change invalidates affected tile positions before rendering any viewport, including positions currently offscreen. Pure raster edits compare immutable source tile identities and map changed source tile bounds through layer rotation/flip/scale with a one-source-pixel interpolation margin. Metadata, dimensions, groups, adjustment or live-mask dependency changes conservatively invalidate the whole grid. Unchanged tiles stay shared. The single full-size normal image fast path reuses its original raster/tile handles.

Painted source bounds conservatively cull transparent regions. Empty/hidden/offcanvas stacks use a shared zero tile. Even visible unsupported or malformed live effects on an otherwise blank canvas are validated by a canonical one-pixel probe and remain explicit errors. A 30000x30000 empty canvas has 13,924 tile handles and one 262,144-byte pixel tile: 484,928 bytes of tile handles plus pixel backing on x64, excluding object/allocator overhead. Fit rendering uses only 64 shared-zero handles at a step of 16. No full RGBA buffer is materialized.

`StackRenderer::renderScaled` keeps original document geometry and changes only the document-space sample center spacing. `RenderRegion` carries the origin and units per pixel to adjustment callbacks, retaining grain continuity between scaled tiles. Normal rendering is unchanged at step one. Lower-resolution output is a canonical point-sampling candidate; it can alias thin features and has not been compared to Mac/Core Graphics view-scale area/interpolation behavior. It must never establish export or Mac parity.

Source `EditorCanvas.swift:869-891` composites only the visible exact document pixels at crisp zoom; lines 674-680 draw layers directly into the view at smaller zoom. Host integration must request the document rectangle visible in the widget on paint, pan, zoom, resize, DPI and document changes; pass `max(1,1/(zoom*devicePixelRatio))`; and draw the patch at `documentOrigin + pixel * unitsPerPixel` while retaining original document dimensions for canvas framing, navigation and overlays. Root owns that NativeCanvas/MainWindow integration.
