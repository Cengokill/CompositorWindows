# Display profile presentation

`platform/DisplayProfile.h` provides read-only monitor discovery and an isolated Direct2D presentation transform. `discoverDisplayProfile(HWND-as-void*)` uses `MonitorFromWindow`, `GetMonitorInfoW`, a display DC for that monitor, and `GetICMProfileW`. It returns the monitor device name, profile path, validated bytes, SHA-256 and an explicit fallback diagnostic. No profile associations, calibration settings or Windows compatibility settings are changed.

The pinned source normalizes imported content to sRGB in `ImageImporter.swift:30,52,57`, creates sRGB export contexts in `ImageExporter.swift:25,93`, and draws canonical images into the current AppKit display CGContext in `EditorCanvas.swift:636–688`. `LayerRenderer.swift:5–25` performs the actual image draw. This module supplies the Windows presentation conversion; it does not modify those canonical document/export semantics. Mac color-managed screen captures remain unavailable.

The loader limits ICC files to 16MiB, requires the declared size to match the complete file, accepts RGB monitor profiles with XYZ/Lab connection spaces, bounds and checks every tag extent, rejects duplicate tag signatures, and asks the Windows color engine to validate the profile. SHA-256 identifies validated bytes. A missing, invalid or unsupported profile produces `AssumedSrgb` with a reason. Corrupted bytes or a changed hash supplied to the converter also cause explicit fallback.

`DisplayColorConverter` owns a reusable Direct3D/Direct2D device and context; hardware creation can fall back to WARP, and tests explicitly force WARP. `convert` takes an immutable premultiplied RGBA8 sRGB buffer and produces a separate presentation buffer for the supplied monitor profile. Both rendering intents are relative colorimetric. Alpha mode is explicitly premultiplied; the output retains each original alpha byte and clamps RGB to alpha, including zero RGB for transparent pixels. Conversion errors restore a fresh copy of the original sRGB pixels and report fallback. This is reversible by discarding the presentation copy; gamut mapping and 8-bit quantization are not mathematically invertible.

The default output-copy budget is 64MiB, checked before pixel validation/copying. Input storage is separate. Conversion uses at most 256 × 256 pixel tiles by default (caller maximum 1,024), with bounded input, target and readback resources. Driver/internal color-engine storage is outside the output counter. No whole-document conversion is intended: call with visible presentation tiles. Discovery/file reads belong on monitor/window/profile-change handling; `convert` performs no file reads. Cache presentation results using immutable source tile identity plus `DisplayProfile::sha256` and clear them when the destination changes. The module is owned by one presentation thread. Returned presentation pixels must never replace canonical rasters or be passed to the exporter.

Windows Advanced Color can intentionally expose no display profile and treat the app's standard integer output as sRGB. The module follows that convention and reports it without probing hidden profile associations or enabling the legacy compatibility helper. HDR/scRGB output, calibrated physical display comparison, automatic per-monitor invalidation and NativeCanvas integration require separate evidence. The standalone module does not claim those integrations are complete. See Microsoft's [Advanced Color profile behavior](https://learn.microsoft.com/en-us/windows/win32/wcs/advanced-color-icc-profiles), [profile query contract](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-geticmprofilew), and [Direct2D ICC effect](https://learn.microsoft.com/en-us/windows/win32/direct2d/color-management).

Seven standalone `/W4 /WX` tests pass in [the recorded run](../tests/display_profile/evidence.json): exact sRGB identity, known linear-RGB conversion, missing/invalid profile fallback, tile partition and budget enforcement, actual monitor discovery, malformed/tag/changed-hash checks, and sRGB → linear-profile → sRGB presentation switching from the same immutable input. The adapter was `Microsoft Basic Render Driver`. The known-profile test compares 256 neutral values at opaque, half-alpha and transparent coverage against the independent sRGB transfer function; maximum error was **1 byte** under a fixed **2-byte** gate. Alpha bytes and input bytes were unchanged. 17-pixel and 1,024-pixel tile partitions produced identical results.

`tests/display_profile/fixtures/linear-rgb.icc` is original generated ICC test data: D50-adapted sRGB primary matrix with gamma 1.0 curves. The generator and manifest pin its 548-byte contents and SHA-256. No external/profile vendor assets are copied. The standard sRGB identity test reads the Windows-installed profile and fails if it is unavailable. The current physical monitor profile was read and hashed; its bytes are not redistributed. These bounded tests claim zero complete upstream test methods and no human display acceptance.

Build the standalone CMake project in `tests/display_profile`, then run `display_profile_tests <case> <absolute-linear-rgb.icc>` for `srgb_identity`, `linear_profile`, `invalid_fallback`, `tile_budget`, `monitor_discovery`, `icc_validation`, and `profile_switch`. Link the production CPP with `d2d1`, `d3d11`, `dxgi`, `dxguid`, `mscms`, `bcrypt`, `gdi32`, and `user32`.
